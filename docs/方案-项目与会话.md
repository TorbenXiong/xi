# 项目与会话方案

项目绑定本地目录，一个会话归属一个项目或独立存在。名称用于展示，规范化目录用于去重。目录是会话组织边界，未来文件执行与权限需另外设计，当前不自动读取文件。

## 已确定行为

- 目录必须现存且绝对；Windows 支持系统选择器，其他入口手动输入。
- 同目录复用项目，归档后重开恢复，不同目录可同名。
- 移除项目解除会话关联，不删除文件和消息；归档隐藏项目及其会话。
- 删除会话永久删除消息和运行记录，归档保留。确认文案区分两种行为。
- 新会话先为草稿，首条消息才保存；直接调用创建 API 则立即创建。
- 聊天明确传服务、模型与会话，按模型能力校验推理值，校验完成才写消息与 run。
- user、assistant 占位及 run 在同一事务保存；网络失败保留输入和部分回复。
- 当前只初始化新结构，不保留旧配置、旧协议或历史数据库迁移兼容逻辑。

## 存储与执行

SQLite 使用 projects、conversations、messages、runs、app_state、providers 和 provider_models。外键约束消息与会话，可空 project_id 表示独立聊天。能力保存来源，支持服务声明、内置预设、逐模型自定义及未知状态。

数据使用平台用户目录，XI_DATA_DIR 可隔离测试。同库只运行一个 Runtime，多个 UI 连接同一业务服务。事务不跨网络请求，全局锁协调聊天与管理，避免迟到回复破坏历史。

## 后续边界

长会话仍发送全部有效历史，后续需增加 token 预算和上下文构建，摘要不能覆盖原记录。FTS5、按会话调度、事件订阅、取消、归档恢复、远程同步及正式 sidecar 分发尚未实现。

模型适配限于 Chat Completions，其他原生协议需独立实现，不能只调整推理值冒充协议适配。详见[模型能力](model-capabilities.md)。
