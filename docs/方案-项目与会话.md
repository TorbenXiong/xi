# 项目与会话方案

项目绑定本地目录，一个会话归属一个项目或独立存在。名称用于展示，规范化目录用于去重。目录是会话组织边界，未来文件执行与权限需另外设计，当前不自动读取文件。

## 已确定行为

- 目录必须现存且绝对；Windows 支持系统选择器，其他入口手动输入。
- 同目录复用项目，归档后重开恢复，不同目录可同名。
- 移除项目解除会话关联，不删除文件和消息；归档隐藏项目及其会话。
- 删除会话永久删除消息和运行记录，归档保留。确认文案区分两种行为。
- 新会话先为草稿，首条消息才保存；直接调用创建 API 则立即创建。
- 聊天明确传服务、模型与会话，按模型能力校验推理值，校验完成才写消息与 run。
- user、assistant 占位及 run 在同一事务保存；网络失败保留输入和部分回复。
- 当前只初始化新结构，不保留旧配置、旧协议或历史数据库迁移兼容逻辑。

## 存储与执行

SQLite 使用 projects、conversations、messages、runs、context_snapshots、app_state、providers 和 provider_models。外键约束消息与会话，可空 project_id 表示独立聊天。能力保存来源，支持服务声明、内置预设、逐模型自定义及未知状态。

数据使用平台用户目录，XI_DATA_DIR 可隔离测试。同库只运行一个 Runtime，多个 UI 连接同一业务服务。事务不跨网络请求，全局锁协调聊天与管理，避免迟到回复破坏历史。

## 上下文预算

输入按 ASCII 每 4 字符、非 ASCII 每字符约 1 token，加消息开销估算；24,576 token 触发压缩，32,768 为输入上限。AppServer 分段汇总最早的未覆盖历史，保留最近两个用户回合；快照记录摘要、覆盖序号、模型和时间，重启后续用，清空或删除会话时移除。原始消息供查看、搜索和导出，不被摘要覆盖。

摘要请求使用当前服务和模型，会增加调用成本与等待时间。摘要为空、超限、截断或调用失败时保留原快照，回退到预算内最近历史；每次最多压缩 8 段，超大历史段也回退裁剪。最新输入始终完整发送，无法容纳时在落库前报错。预算是本地估算值，尚未按模型窗口及输出/推理预留动态调整；摘要有信息损失，亦未提供手动压缩入口。

## 当前边界

归档与恢复已实现：项目归档会隐藏项目及其会话；恢复项目后，归档会话仍需单独恢复。恢复会话时必须使用会话 ID，或使用唯一的标题；重复标题必须改用 ID。归档项目按项目 ID、完整目录或唯一名称恢复，重复名称必须改用 ID 或完整目录。

## 后续边界

FTS5、按会话调度、事件订阅、取消、远程同步及正式 sidecar 分发尚未实现。

模型适配限于 Chat Completions，其他原生协议需独立实现，不能只调整推理值冒充协议适配。详见[模型能力](model-capabilities.md)。
