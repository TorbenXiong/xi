# Runtime 发布与自动标题修复任务卡

## 目标与基线

- **用户触发**：项目评估后，用户指定修复桌面发布漏带 Runtime 和自动会话标题未清洗两项问题；开发版测试后要求提交、PR、审阅和合并。
- **期望结果**：发布构建带上当前平台的 release Runtime；首条消息生成的标题为最多 24 个字符的单行文本，消息原文不变。
- **分支**：`fix/runtime-bundle-and-session-title`，基于 `022bba4`。
- **原始问题**：release 桌面端从可执行文件同目录查找 Runtime，但打包配置未包含它；`start_run` 直接取输入前 24 个字符，换行和控制字符会进入数据库标题。
- **调用链**：发布脚本 → Cargo Runtime 产物 → Tauri resources → 桌面启动/监督器；HTTP/CLI → AppServer → `Store::start_run` → workspace/export。
- **范围**：不变更数据库结构、公共 API、依赖或真实凭据；不迁移已有标题，不清洗用户手动指定的标题。

## 实施与验收

- `scripts/build-desktop.mjs` 离线构建 Runtime，暂存到 `src-tauri/runtime/`，调用本地 Tauri CLI；正常返回或异常时清理自己的暂存副本，已有文件拒绝覆盖。
- Tauri 资源目录在开发检查时始终存在；release 构建缺少 Runtime 时直接失败，避免生成漏带服务的产物。
- 桌面端通过 Tauri resource directory 定位 Runtime，开发版仍使用根项目 debug Runtime。
- 自动标题合并连续空白及控制字符，去除首尾空白，按 Unicode 字符取 24 个并再次去掉尾部空格；清洗为空时使用“新会话”。
- 存储回归测试覆盖多行、控制字符、中文截断、截断后的尾空格、空标题回退、消息原文、导出标题、后续消息与手动重命名。
- 发布脚本保护测试使用中文和空格临时目录，不运行真实模型、不使用真实凭据。
