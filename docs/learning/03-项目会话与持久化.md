# 第三步：目录项目、会话与持久化

项目绑定现存的本地文件夹，按目录组织会话。一个会话归属一个项目或独立存在，没有系统“未分组”记录。目录目前只用于组织，不自动读取项目文件。

## 项目生命周期

创建需要绝对目录，后端规范化路径并验证文件夹。目录唯一，名称可重复；名称留空使用文件夹名。同目录复用 ID，归档后重新打开恢复显示。

移除项目在事务中把会话 project_id 置 null，再移除项目，不删除会话或目录文件。归档隐藏项目及会话，保留记录。独立会话显示在“聊天”区域。

## 存储入口

阅读 src/storage.rs 的 Store::open：创建父目录，打开 SQLite，启用外键、WAL 与忙等待，创建当前表，再初始化模型服务表。当前未上线，不维护旧版本迁移、系统分组或 JSON 快照导入。

Windows 默认 %LOCALAPPDATA%\xi\xi.db，其他平台见 [README](../../README.md)。XI_DATA_DIR 可指定独立空目录。密钥在本地数据库中，测试使用临时库，不读取真实数据。

| 表 | 内容 |
| --- | --- |
| projects | ID、名称、唯一目录、时间戳与归档时间 |
| conversations | ID、可空项目 ID、标题、最近模型、时间戳与归档时间 |
| messages | 会话 ID、唯一递增 sequence、角色、内容、状态与错误 |
| runs | 用户/回复消息 ID、模型、状态、时间与错误 |
| app_state | 默认项目和会话等轻量状态 |
| providers | 名称、地址、Key 与默认服务状态 |
| provider_models | 模型 ID、推理选项 JSON 与能力来源 |

## 一轮请求

~~~text
选定服务、模型、推理和会话
  → AppServer 校验全部参数
  → 事务创建 user complete、assistant streaming、run running
  → 释放数据库锁，请求模型
  → 流式增量节流落库（CLI）
  → complete_run 或保存 failed/interrupted
~~~

消息成功状态为 complete，run 为 completed。只有完整消息进入后续上下文；失败/中断回复保留供查看和导出，空失败回复也不能过滤。

校验失败不写入消息。有效请求遇到网络错误时，输入已落库，错误与部分文本会保存。启动将遗留活动请求标为 interrupted，不能把断开的请求伪装为成功。

## 事务与并发

用户消息、assistant 占位和 run 在同一事务创建。清空、删除、项目移除和模型缓存替换也使用短事务，不跨网络调用持有数据库锁。流式首块立即保存，后续按时间/字节数节流，结束和错误时保存最终文本。

同库只允许一个 Runtime，文件锁防止第二个进程错误恢复正在执行的请求。多个 UI 连接同一服务。AppServer 当前用全局锁协调聊天及管理操作，尚未实现按会话并发与取消。

## 客户端和 CLI

React 新会话先是内存草稿，首条消息才创建数据库会话。列表、历史、搜索和导出均经 XiClient 访问 AppServer。默认项只用于初始化和 CLI，聊天明确传服务、模型和会话 ID。

CLI 使用 /project-open、/project-use、/project-move 等命令；/project-use - 为独立聊天，/models、/model、/reasoning 设置模型与推理。/help 查看参数，旧分组命令和别名已删除。

## 验证

Rust 测试覆盖目录规范化/去重、移除项目后保留会话、消息状态、恢复与搜索。Node Runtime 测试使用含中文和空格的临时目录、本机 mock 服务，覆盖归档重开、独立聊天、CLI、目标隔离、推理校验和部分回复保存。
