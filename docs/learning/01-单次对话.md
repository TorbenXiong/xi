# 第一步：调用模型完成单次对话

这一节关注一次模型请求的最小链路。现有项目已加入持久化和桌面端，完整演进见 [03-项目会话与持久化](03-项目会话与持久化.md)和 [04-应用端架构与调试](04-应用端架构与调试.md)。

```text
React → XiClient → HTTP → AppServer → ModelRuntime → Chat Completions API → 回复
```

## 阅读代码

- `src/protocol.rs` 的 `Message`：`role` 表示消息角色，`content` 表示文本。
- `src/model.rs` 的 `ChatRequest`：模型 ID、消息历史和可选推理强度；CLI 设置流式请求，桌面 API 等待完整结果。
- 同文件的 `call_model`：向 `{base_url}/chat/completions` 发起请求，检查状态、响应大小与 JSON 格式。
- `ChatResponse`：从 `choices[0].message.content` 提取回复。

Provider 地址和 API Key 在桌面配置页保存，模型在对话区选择。模型 ID 必须是服务商支持的 ID；界面显示名称不能代替协议字段。

一次请求成功只证明模型服务可用，不能证明桌面 WebView 的跨源请求、Token 或持久化正常。这些链路需要分别验证。
